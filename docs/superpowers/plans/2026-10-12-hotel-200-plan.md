# Hotel 200 Conversation QA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Execute and review 200 realistic linked customer turns and deliver their actual replies as TXT.
**Architecture:** A diagnostic-only worker batches independent synthetic conversations with the production AI instructions and approved hotel facts. Python validates outcomes in isolated test state; ordinary single-turn production routing reproduces defects before fixes. Real provider failures remain visible.
**Tech Stack:** Existing Flask/Python service, Groq JSON inference, GitHub/Render.
**Spec:** docs/superpowers/plans/2026-10-12-hotel-200-spec.md

## Global Constraints
No real customer/staff sends or operational writes. Exactly 200 distinct guest messages in 20 linked chats. Actual previous replies become history. Model/attempt/limitations are retained. AI understands and writes; Python validates/executes actions. Existing functions preserved.

## Review Focus
- Short omitted-subject price questions retain the last actual item.
- New-topic messages do not modify pending carts or check-in state.
- Unknown stock/preparation never becomes confirmed availability.
- Sender-bound records never expose other guest bills or bypass payment proof.
- Provider failure, incomplete JSON or missing rows cannot be counted as a successful answer.
